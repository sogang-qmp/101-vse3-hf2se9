Goal

Two things before the level-corrected transport: (1) confirm the conductance is converged once the scattering region (the central device between the two semi-infinite VSe₃ electrodes) is made longer, and (2) compute the B3LYP→vdW-DF2 molecular-orbital energy shifts $\Delta_i$ that feed the DFT+Σ correction.

B. B3LYP molecular-level correction (DFT+Σ) — inputs

The semi-local functional (vdW-DF2) underestimates the molecular gap, so the transmission resonance is mis-placed at $E_F$. The correction is a DFT+Σ level alignment: each molecular orbital is shifted by $\Delta_i = \varepsilon_i^{\text{B3LYP}} - \varepsilon_i^{\text{vdW-DF2}}$ and added to the device Hamiltonian as

$\displaystyle \Delta H = S\,C\,\mathrm{diag}(\Delta_i)\,C^{\dagger}\,S,$

with $S$ the overlap and $C$ the isolated-molecule MO coefficients — the in-device molecular block has no clean molecular levels here (Hf₂Se₉ is covalently fused into the chain), so an MPSH projector cannot be used; construction detail in Methods: DFT+Σ. From the vacuum molecule (vdW-DF2 in SIESTA vs B3LYP in VASP, vacuum-level aligned) the gap opens 0.02 → 0.75 eV with a strongly asymmetric shift — occupied levels drop ≈ 1 eV ($\Delta_\text{HOMO} = -1.01$ eV) but virtual levels only ≈ 0.1–0.3 eV ($\Delta_\text{LUMO} = -0.29$ eV). The device transport uses the same vdW-DF2, so the correction functional is consistent.

C. Corrected transmission — DFT+Σ applied

We built $\Delta H = S\,C\,\mathrm{diag}(\Delta_i)\,C^\dagger S$ from the isolated-molecule MO coefficients $C$ projected onto the device molecular block (Hf₂Se₉, atoms 107–117), wrote it as a level-1 deltaH.dH.nc, and recomputed $T(E)$ with TBT.dH (N25_k100, 0 bias, η = 0.005 eV).

Discussion / next

What is actually implemented already: TBtrans already has the runtime hook for an additive Hamiltonian/self-energy correction, and sisl already has the file writer for that hook. The official TBtrans manual states that the electronic structure can be changed as $H \leftarrow H + \delta H + \delta\Sigma$, and defines TBT.dH as the fdf flag for the NetCDF4 file containing the $\delta H$ data. In sisl, sisl.io.tbtrans.delta implements the matching .dH.nc writer/reader: write_delta stores level-1 static terms when no E or k is supplied, and also supports k-dependent, E-dependent, and E+k-dependent delta files.

What is not automatic: there is no project-specific DFT+Σ button that knows our molecular orbitals or B3LYP shifts. We still have to construct the actual molecular projector correction, $\Delta H = S\,C\,\mathrm{diag}(\Delta_i)\,C^\dagger S$, write that matrix with sisl as a level-1 deltaH.dH.nc, then tell TBtrans to use it with TBT.dH deltaH.dH.nc. The source-patch part is unnecessary because the file-based δH insertion path already exists; the physics/mapping step is still our implementation task.
